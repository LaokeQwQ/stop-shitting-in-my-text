# 按文体：痕迹与改法

同一个句式在不同文体里的可接受度不一样。先确定读者要拿这段文字做什么，再判断哪些痕迹必须改。用户逐条列举的痕迹见 `cases.md`。

## 1. 周报 / 汇报

读者只想知道三件事：做完了什么、卡在哪、下一步要谁做什么。

常见痕迹：

- 围绕……展开；有效提升；取得阶段性成果；持续深化；赋能业务。
- 把日常动作写成战略：“推进了数据治理体系建设”。
- 只写过程不写结果，或者只写结果不写口径。

改法：

- 每项写“动作 + 结果 + 数字 + 卡点”。没有数字就写交付物。
- 卡点必须具体到人、系统或外部依赖。
- 下一步写动词和日期，不写“持续跟进”。

Before:

> 本周围绕数据质量提升，持续推进治理工作，取得阶段性成果，有效支撑了业务发展。

After:

> 订单表里 12 个字段的空值率从 8% 降到 1.2%。还剩两个问题：退款表的时区没统一，需要财务确认口径；清洗脚本周五上线，等运维开权限。

## 2. 产品文案 / 落地页

读者在五秒内要知道这东西替她省了什么。她不相信形容词，只相信场景。

常见痕迹：

- 一站式、无缝、强大、重新定义、开启新篇章、为……提供有力支撑。
- 堆叠定语：`可编辑、可定制、可追溯的数据平台`。
- 没有来源的“数千家客户”“行业领先”。

改法：

- 一句一个具体收益；给使用场景；不编客户和数字。
- 把功能名换成用户动作：不是“多维度筛选”，是“按门店、日期、SKU 三个条件一起筛”。
- 价格、限制、迁移成本要写出来。藏起来的成本会在售后爆炸。

Before:

> 一站式智能数据平台，强大的分析能力，无缝对接你的业务，助力企业实现数字化转型。

After:

> 把门店 Excel 拖进来，十分钟后看到按 SKU 的毛利。缺货的门店会标红，点一下生成补货单。按门店数收费，第一家免费。

## 3. 公众号 / 长文

读者给的是注意力，不是耐心。开头要有具体的人或事，中间要有作者自己的判断。

常见痕迹：

- 在这个……的时代；随着……的发展；让我们深入探讨。
- 不是……而是……连用；三段排比；每节结尾升华。
- 引用“研究表明”但没有研究。

改法：

- 第一段写场景，第二段写冲突，观点跟着证据走。
- 一个观点只出现一次。第二次出现必须加新证据。
- 结尾停在事实上，不要“未来可期”。

## 4. 小红书 / 社媒

读者在判断“这是不是广告”和“这人是不是真的用过”。真实感来自具体和不对称，不来自网络词。

常见痕迹：

- 姐妹们、绝绝子、宝藏、氛围感拉满。AI 模仿人类口癖，密度一高反而更假。
- 三项排比加 emoji：`好用、好看、好便宜 ✨`。
- 每段都是短句，每句都带感叹号。

改法：

- 写一次真实经历，保留不完美：多少钱、排队多久、哪里踩坑。
- 不要为了“网感”堆网络词。作者平时怎么说就怎么写。
- emoji 只在作者本来就用的情况下保留。

## 5. 邮件 / IM

收件人读完要知道做什么。邮件不是展示文采的地方。

常见痕迹：

- 希望这封邮件找到你；感谢您抽出宝贵时间；如需进一步信息请随时告知。
- 三段背景之后才说请求。
- 用“同步一下”“对齐一下”代替具体动作。

改法：

- 第一句说目的，第二句说需要的动作和截止时间，其余删。
- 主题行写动作和对象，不写“关于……的沟通”。
- 一件事一封邮件。抄送名单砍到真正需要知道的人。

Before:

> 您好，希望您一切顺利。为了更好地推进项目，我们想就相关事宜与您对齐一下，不知您何时方便？

After:

> 需要你在周四前确认测试账号的权限范围。现在只有只读权限，压测跑不了。确认后我这边当天开跑。

## 6. 简历 / 自我介绍

读者在判断两件事：这人做过什么规模的活，能不能马上上手。

常见痕迹：

- 负责……工作；参与……项目；具备良好的沟通能力；熟练掌握。
- 形容词代替规模：`大幅提升系统性能`。
- 每段都是“主导/负责/参与”三件套。

改法：

- 动词开头，给规模（用户数、QPS、预算、团队人数）和结果（延迟、成本、转化）。
- 不写“精通”。写你用它在什么约束下解决了什么问题。
- 一段只放最能证明能力的那件事。

Before:

> 负责后端系统优化，具备良好的团队协作能力，熟练掌握多种编程语言。

After:

> 把订单查询从 1.8 秒降到 220 毫秒：加了复合索引，拆掉一个 N+1 查询，缓存命中率做到 93%。带过 3 人小组，和支付团队一起把对账差异从每天 40 笔降到 2 笔。

## 7. 技术文档 / README

读者要照着做完。文档的第一目标是可执行，不是显得专业。

常见痕迹：

- 本文将介绍；首先……其次……；强大的功能；无缝集成；请注意。
- 只有概念解释，没有最小示例。
- 参数没有类型、默认值、边界；错误信息只说“失败了”。

改法：

- 先给最小可运行示例；再给参数、返回值、错误码。
- 每个警告写清触发条件和修法。
- 删掉营销形容词。技术读者会把“强大”当成噪音。

## 8. 演讲 / 发言稿

读者用耳朵接收。句子要能一口气念完，观点要能停住。

常见痕迹：

- 三个排比；宏大开头；“让我们共同……”；书面连接词。
- 每句都是 30 字以上，没有换气点。
- 结尾口号化。

改法：

- 读一遍，删掉念不顺的句子。
- 一段只留一个观点。重要的话单独成句。
- 用具体故事代替概括。故事里要有时间、地点、一个人。

## 9. 公关稿 / 新闻稿

读者要能核验：谁、做了什么、什么时候、对谁有影响、哪里能查。

常见痕迹：

- 里程碑；新篇章；引领行业；深度布局；赋能生态。
- 没有出处的“行业首个”。
- 高管引语像产品说明书。

改法：

- 导语给事实；引语必须真实；背景一段说完。
- 没有可核验信息就不发，或者改成内部通稿。
- 数字给口径和统计周期。

## 通用判断

同一段出现三类以上痕迹，重写。只有一类，改那一处，不要动全文。改完读一遍：如果读起来像另一个模型刚洗完，回到 `rewrite-recipes.md` 的“改完更像 AI 的六种情况”。
